## Defect found and fixed by this round's tests

`test_arc_load_fuzz` failed under GCC on a valid in-memory corpus.
Root cause (test-harness, not engine): `DroneBrain(const DroneConfig&)`
never initialized its `arc_plasticity_config pcfg` member, and `build()`
branches on `pcfg.w_phase_count == 0` — an uninitialized read. MSVC's
zeroed stack masked it; GCC's did not (corrupt v2 header fields at bytes
48+, rejected by `arc_brain_validate_header`). Fixed by value-initializing
`pcfg` in the constructor (`train/sim/drone_env.hpp`). Goldens unchanged:
the MSVC corpus was already byte-correct, so the pin hashes hold.
